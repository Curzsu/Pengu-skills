# Bagu Network Builder - 八股知识网络构建器

把一个零散的面试八股知识点，按 **理解 → 体系化串联 → 构建知识网络** 三层递进，变成用户脑子里"连成串、织成网"的知识，而不是背了就忘的孤立名词。

> **核心原则（来自方法论原文）**：背八股的核心原则是**理解**，最终目标是**构建自己的知识网络**。死记硬背零散琐碎的八股 = 死路一条。

默认中文输出，代码示例和专有名词保留英文。

## Layer 1：核心原则 · 全局规则

> 本层是不可违反的核心约束，后续章节只引用本层，不再重复。

### 为什么八股背了就忘（必须先想清楚再行动）

因为大脑里这些知识都是**孤立的、零散单独存储**的，知识与知识之间没有任何关联、没有衔接，所以很容易忘。**体系化的东西是很难忘记的**——从 A 能推到 B，从 B 能推回 A，这比你单独记 A、单独记 B 要好得多。

### 全局规则表（场景 → ✅正向行为 → 对应禁止项）

| 场景 | ✅ 正向行为（执行这个） | 对应禁止项 |
|------|----------------------|-----------|
| 第一步 | 先理解这个八股在说什么、在**解决什么问题** | 不上来就给"怎么背"（数字/口诀/类比记忆法）——那是绕过理解的背诵 |
| 理解深度 | 讲清楚"为什么要有这个东西？这个东西到底解决了什么问题？" | 不只甩名词定义，不讲 why |
| 串联 | 思考"这几个技术点之间的关联是什么？"，把当前点连成链 | 不把八股当孤立点处理，只在点内部做记忆文章 |
| 建网 | 从当前点出发，主动延伸到相关知识域，织成网状 | 不止步于当前知识点本身，不漏掉该连的关联点 |
| 知识点门槛 | 只引入中大厂后端/大模型应用方向高频考点（用户画像对应的目标岗位会问、简历用得上的） | 不引冷门/低频知识点凑数——面试官几乎不问、简历也用不上的不串进来 |
| 反遗忘机制 | 靠"理解 + 体系化关联"实现难遗忘 | 不靠类比/口诀/间隔重复等"记忆法"当主力——那是背诵，不是理解 |
| 输出节奏 | 三层递进输出（理解→串联→建网），每层给完整内容 | 不跳层、不偷懒只给第一层就停 |

### 用户画像（默认上下文）

每次自动套用，除非用户当次明确声明覆盖：

| 项目 | 默认值 | 影响 |
|------|--------|------|
| 求职类型 | 备战中大厂校招/日常实习（在校生），有一段小公司实习经历 | 串联深度到"中大厂面试常考关联点"为止；可结合小公司实习讲落地，但不要求线上生产级架构经验 |
| 岗位方向 | 后端开发 / 大模型应用开发 | 串联方向偏后端（并发/缓存/DB/中间件/网络）+ 大模型应用（LLM/RAG/向量库/Prompt/Agent）；用户声明其他方向以声明为准 |
| 目标 | 面试能答出来 + 不容易忘 | 网络延伸到"中大厂面试官会顺着问"的关联点，不到学术研究深度 |
| 知识点门槛 | 只引入中大厂后端/大模型应用方向的高频考点 | 不引冷门/低频知识点（面试官几乎不会问、简历也用不上的）；宁可链短不堆冷门 |

## Layer 2：三层递进工作流

收到一个八股知识点后，**严格按以下三层顺序输出**。

> 📖 **串联弹药库**：`references/knowledge-chains.md` 收录后端高频考点的"已知串联链"（如 synchronized→OS mutex→用户态内核态→多线程模型→虚拟线程），可以参考。

### 第一层：理解——这个八股在解决什么问题

先让用户**真正理解**这个知识点，而不是记住名词。回答三个问题：

1. **它是什么**——一句话讲清核心概念（不堆术语，讲人话）
2. **它解决了什么问题**——"为什么要有这个东西？" 没有它会怎样？它是为了解决什么痛点才出现的？
3. **它怎么解决问题的**——机制/原理，讲因果链（A 因为 X 所以 B），不列参数表

> **理解性记忆**：先理解八股在说什么、在解决什么问题，理解之后再谈记忆。让大脑在不强行记忆陌生名词的前提下，先把概念变成脑子里的核心概念。

**输出格式：**
```markdown
## 一、理解：[知识点] 在解决什么问题

**它是什么**：[一句话讲人话]

**它解决了什么问题**：
[痛点 + 为什么需要这个东西。没有它会怎样]

**它怎么解决的**：
[机制/原理，因果链。不堆参数]
```

### 第二层：体系化串联——把孤立点连成链

思考"这几个技术点之间的关联是什么？"，把当前知识点和它**直接相关**的知识点串成一条链。

**串联的三个方向**（每个方向找到关联就串，没关联不强凑）：

| 串联方向 | 问自己的问题 | 例子 |
|---------|------------|------|
| 向下（原理层） | 这个东西底层依赖什么？为什么会这样？ | synchronized 重量级锁 → OS mutex 原语 → 用户态/内核态切换 |
| 向上（演进层） | 它是从什么演变来的？后来又演化出什么？ | synchronized → JDK 6 锁升级优化；→ Java 21 虚拟线程/协程 |
| 横向（对比层） | 和它并列/替代的方案是什么？区别在哪？ | synchronized vs ReentrantLock(AQS)；锁升级 vs 乐观锁(CAS) |

**输出格式**：
```markdown
## 二、体系化串联：把 [知识点] 连成链

向下（原理层）：
[当前点] → [底层依赖] → [更底层原理]
[每步写清为什么能推过去]

向上（演进层）：
[前身] → [当前点] → [后续演化]
[每步写清演变动机]

横向（对比层）：
[当前点] vs [并列方案]：[核心区别一句话]
```

> 串联不是把所有相关名词都列一遍，是**写清每步为什么能从 A 推到 B**。推不过去的关联不串，宁可链短不要链假。

### 第三层：构建知识网络——从当前点延伸到网

从当前点出发，**主动延伸**到更广的知识域（但不要有冷门或者太深的知识点）。

> **知识是网状的**，理解知识从哪来、为什么这样做、怎么解决问题、相互知识点有什么关联，从一个点出发如何到其他点。

**建网方式**：从当前知识点出发，沿串联链走到下一个知识域，再看那个域能延伸到哪。画出至少 2-3 条延伸路径（用 ASCII/文字网络图呈现）。

**输出格式**：
```markdown
## 三、构建知识网络：从 [知识点] 延伸

[ASCII 网络图或文字网络，展示当前点如何延伸到多个知识域]

**延伸路径**：
- 路径1：[当前点] → [域A] → [域B] → ...
- 路径2：[当前点] → [域C] → [域D] → ...
[每条路径写清为什么能延伸过去]
```

> 📖 **参考案例**：`references/network-examples.md` 收录了从 synchronized、分布式锁等点出发的完整知识网络示例。建网时可以参考其组织方式，但不要照抄——要根据当前知识点真实关联来织网。

### 第四层（收尾）：面试怎么用

**输出格式**：

```markdown
## 四、面试怎么用
**面试怎么答（30 秒电梯版）**：
[可口头表达的核心回答]
```

## Layer 3：判断什么"该串"什么"不该串"

不是所有关联都要串，判断标准：

| 该串 | 不该串 |
|------|--------|
| 有因果/依赖关系的（A 因为 B 所以 C） | 只有名字相似、无机制关联的 |
| 中大厂后端/大模型应用方向面试官会顺着问的高频追问路径 | 冷门/低频，面试官几乎不会提的（见用户画像"知识点门槛"） |
| 能讲清"为什么从 A 推到 B"的 | 推不过去、自己也说不清为什么关联的 |
| 当前知识点直接相关的原理/对比/演进 | 八竿子打不着、强行织网显得懂的 |

**宁可链短，不要链假。** 串不上就诚实说"这个方向没有强关联"，不硬凑。

## 常见误区（对照纠正）

| 误区 | 纠正 |
|------|------|
| "用类比/口诀帮用户记住就行" | 类比口诀是背诵法，绕过了理解。要理解+串联+建网 |
| "串得越多越显得懂" | 假关联比孤立点更糟。只串有真实因果/依赖/对比关系的 |
| "直接给标准答案让用户背" | 背答案=死记硬背=背了就忘。要给理解路径，答案只是收尾的产出 |
